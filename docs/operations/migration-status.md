# Состояние Docker Compose-миграции

Последняя проверка: **26 октября 2026 года**.

## Итог

Миграция завершена успешно. Три независимых Compose-проекта `front`,
`directus` и `database` заменены единым проектом `parks`, который запускается
из `/root/front/parks-2/compose.yaml`.

По результату `docker compose ls` на VPS работает только один Compose-проект:

```text
parks  running(4)  /root/front/parks-2/compose.yaml
```

В него входят четыре сервиса:

- `database` — PostgreSQL/PostGIS 14;
- `directus` — Directus 11.3.5;
- `parks-front` — Next.js;
- `pgadmin` — pgAdmin.

## Сохранность данных

Новые тома с пустыми данными не создавались. Единый Compose подключает прежние
external volumes:

- `database_database` → `/var/lib/postgresql/data`;
- `directus_uploads` → `/directus/uploads`;
- существующий volume pgAdmin → `/var/lib/pgadmin`.

Все сервисы используют существующую внешнюю сеть `my-app-network`.

Важно: нельзя выполнять `docker compose down -v` и нельзя удалять перечисленные
volumes. Обычная команда `docker compose down` тома с данными не удаляет,
поскольку они объявлены как external.

## Подтверждённые проверки

- `docker compose config --quiet` завершился с кодом `0`;
- все четыре контейнера запущены без циклических перезапусков;
- PostgreSQL имеет статус `healthy` и принимает подключения;
- Directus `/server/health` возвращает `{"status":"ok"}`;
- frontend локально и через публичный домен возвращает `200 OK`;
- Directus через публичный домен перенаправляет в `/admin`;
- pgAdmin возвращает штатное перенаправление на страницу входа;
- страницы frontend получают данные и файлы из Directus;
- Apache завершает проверку конфигурации сообщением `Syntax OK`;
- существующие домены продолжают работать через прежние Apache VirtualHost.

Ответы `204` на изменения записей Directus, `206` при частичной загрузке файлов
и `302` при переходе к страницам входа являются штатными.

## Reverse proxy

На VPS используется **Apache httpd**, а не Nginx. Он установлен на хосте и не
входит в Compose. Внешний TLS завершается на инфраструктуре хостинг-провайдера.

Текущие upstream-порты сохранены без изменения:

- основной сайт → `127.0.0.1:3020`;
- Directus → `127.0.0.1:8055`;
- pgAdmin → `127.0.0.1:5050`.

Во время миграции конфигурация Apache не изменялась и его перезапуск не
потребовался.

## Резервные копии и возврат

Перед переключением были созданы и проверены:

- архив конфигураций старых Compose-проектов и Apache;
- PostgreSQL custom-format dump и его читаемый список содержимого;
- свежий PostgreSQL dump непосредственно перед переключением;
- архив Directus uploads размером около 3,3 ГБ;
- архив данных pgAdmin.

Архив Directus uploads скачан на локальный компьютер, его SHA-256 совпал с
контрольной суммой. После проверки локальной копии большой архив был удалён с
VPS для освобождения места. Архив pgAdmin также был скачан локально.

Старые Compose-файлы пока следует сохранить для контролируемого rollback.
Восстанавливать данные из архивов при обычном rollback не требуется: прежняя
и новая конфигурации используют одни и те же external volumes.

## Период наблюдения

До закрытия периода наблюдения нужно:

1. Проверить вход и редактирование существующей записи в Directus.
2. Проверить загрузку и отображение нового файла.
3. Проверить основные и внутренние страницы сайта в браузере.
4. Проверить вход в pgAdmin и подключение к базе.
5. Убедиться, что контейнеры корректно поднимаются после планового перезапуска.
6. Несколько дней наблюдать за свободным местом и ростом Docker-логов.

Базовые команды контроля:

```bash
cd /root/front/parks-2
docker compose ps
docker compose logs --since=1h
df -h /
docker system df
```

После периода наблюдения работу следует продолжить по
[списку технического долга](technical-debt.md).
